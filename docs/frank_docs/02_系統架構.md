# DSAS 系統架構文件（可上架版本）

> **DSAS — Data Sovereignty as Soul**
> 本文件描述一個**可實際運行、可公開上架**的系統架構：東西放在哪裡、AI 怎麼跑、各組件如何協作。整合了 Web3Auth（無門檻登入）、ERC-721/6150（身分）、Arweave/Irys（永久儲存）、Lit Protocol（存取控制）、LoRA/RAG/LLM（記憶與對話）、ElevenLabs（聲音）、Simli（視訊化身）與 LiveKit（公祭與串流）。

---

## 一、四層架構總覽

| 層級 | 技術 | 角色 | 資料放哪 |
|---|---|---|---|
| **登入 / 身分層** | Web3Auth + ERC-721 + ERC-6150 | 無門檻登入、所有權證明、家族層級 | 區塊鏈（Polygon / Base） |
| **存取控制層** | Lit Protocol | 加密、解密授權、「持 NFT 才能看」 | Lit 去中心化節點網路 |
| **儲存層** | Arweave + Irys | 永久儲存照片/影片/音檔/文字/AI 模型 | Arweave permaweb |
| **運算層** | LoRA + RAG + LLM + ElevenLabs + Simli + LiveKit | 即時重現外貌、聲音、人格、視訊 | GPU + 雲端 API |

四層之間透過一個**薄後端（NestJS / FastAPI）** 協調，但後端**不是權威來源**——所有權在鏈上，資料在 Arweave，後端只做加速與編排。

## 三、登入 / 身分層

### 3.1 Web3Auth：把 Web3 門檻降到零

家屬不需要懂助記詞。流程：

1. 點「用 Google / LINE 登入」
2. Web3Auth 透過 MPC（多方計算）在背後生成錢包，私鑰碎片化分散保管
3. 使用者體感 = 一般 App 登入；實際上已擁有一個可簽署鏈上交易的錢包
4. 進階使用者可改連 MetaMask / Rabby，把資產轉至自持錢包

### 3.2 智能合約該定義什麼

這是你問的「智能合約該寫什麼、定義哪些東西」。核心合約 `DigitalTablet.sol` 應包含：

**(A) 身分與所有權（ERC-721 基礎）**
```solidity
// 每張塔位是獨一無二的 NFT
function mintRoot(address to, string tokenURI) external onlyMinter returns (uint256);
function ownerOf(uint256 tokenId) external view returns (address); // 誰是合法持有人
function transferFrom(address from, address to, uint256 tokenId);    // 繼承 / 轉移
```

**(B) 家族層級（ERC-6150）— 純逝者譜（方案 A）**

> **核心設計:塔位 NFT 只為已逝者鑄造,活人不鑄 NFT、不佔家族樹節點。** 家族樹是一棵「純逝者譜」,只有逝者是節點;活人的角色是「持有並管理塔位的守護者」,以及被授權的家族成員(授權地址,非 NFT 節點)。當某位家族成員過世,才為其鑄造塔位並用 `safeMintWithParent` 接到其已逝長輩底下,家譜自然往下長一代。

```solidity
mapping(uint256 => uint256)   parentOf;    // 子 → 父（僅逝者之間的血緣鏈）
mapping(uint256 => uint256[]) childrenOf;  // 父 → 子（家譜反向索引）

function mintRoot(address to, string tokenURI) external onlyMinter returns (uint256);
function safeMintWithParent(address to, uint256 parentId, string tokenURI) external returns (uint256);
function isRoot(uint256 tokenId) external view returns (bool);
function childrenOf(uint256 tokenId) external view returns (uint256[] memory);

// 活人「守護者 / 家族成員授權」——不是 NFT 節點,而是地址 + 角色
enum Role { NONE, VIEWER, UPLOADER, ADMIN }
mapping(uint256 => mapping(address => Role)) public familyRole;

function grantFamilyRole(uint256 tokenId, address member, Role role) external onlyOwner;
function revokeFamilyRole(uint256 tokenId, address member) external onlyOwner;
```

**GitHub 類比**:塔位 NFT = repo;持有人 = owner;`familyRole` 授權的家族成員 = collaborator(VIEWER/UPLOADER/ADMIN 對應 read/write/admin);ERC-6150 父子關係 = 逝者血緣鏈,與「誰能存取」是兩條獨立的線。新增子孫不是發 NFT 給活人,而是 `grantFamilyRole` 授權地址。

**(C) 資料指針（指向 Arweave）**
```solidity
mapping(uint256 => string) tokenURI;      // 公開 metadata（姓名/生卒/大頭照）
mapping(uint256 => string) artifactURI;   // AI 訓練產物的 Arweave 位址（可更新）

function setArtifactURI(uint256 tokenId, string uri) external onlyHolderOrAdmin;
```

**(D) 權限與公開/私密狀態**
```solidity
mapping(uint256 => mapping(bytes32 => uint8)) visibility; // 每個資產的可見層級
function setVisibility(uint256 tokenId, bytes32 assetId, uint8 level) external onlyOwner;
// Lit Protocol 會讀取這個狀態決定要不要發解密鑰匙
```

**(E) 死亡開關 / 繼承**
```solidity
mapping(uint256 => address)  successor;     // 預設繼承人
mapping(uint256 => uint256)  lastActiveAt;  // 最後活躍時間戳

function setSuccessor(uint256 tokenId, address heir) external onlyOwner;
function heartbeat(uint256 tokenId) external onlyOwner;      // 登入即更新活躍時間
function claimInheritance(uint256 tokenId) external;         // 逾期未活躍，繼承人接手
```

**(F) 事件（讓前端 / Lit 監聽）**
```solidity
event TabletMinted(uint256 tokenId, address owner, uint256 parentId);
event VisibilityChanged(uint256 tokenId, bytes32 assetId, uint8 level);
event InheritanceClaimed(uint256 tokenId, address from, address to);
```

## 四、存取控制層：Lit Protocol

### 4.1 它解決什麼

**問題**：NFT 在鏈上 100% 公開，任何人都能查到「這張塔位存在、屬於王家」。但塔位裡鎖著的**私密大檔案（相簿、LoRA 模型、高清影片）絕不能讓路人看到**。

**Lit Protocol 的角色 = 去中心化的 24 小時保全車隊**：

- 爺爺的照片加密後放進 Arweave（保險箱）
- 解密鑰匙**不在任何一台伺服器**，而是碎片化分散在全球幾十台 Lit 節點
- 有人想看 → 必須向 Lit 節點群證明「我持有對應 NFT」（錢包簽名）
- 節點群各自核對鏈上 `ownerOf` / `visibility` 狀態 → 集體在空中把鑰匙拼起來解密 → 看完鑰匙立刻拆碎收好

**安全性**：就算幾台 Lit 節點被駭，駭客也拿不到完整鑰匙。

### 4.2 存取控制條件（Access Control Conditions）

Lit 用「條件」決定誰能解密，例如：

```js
// 條件範例：必須持有 tokenId=42 的塔位 NFT 才能解密
const accessControlConditions = [{
  contractAddress: "0x...DigitalTablet",
  standardContractType: "ERC721",
  chain: "polygon",
  method: "ownerOf",
  parameters: ["42"],
  returnValueTest: { comparator: "=", value: ":userAddress" }
}];
```

公開切換時，持有人簽名修改鏈上 `visibility`，Lit 下次核對就會放行路人。

### 4.3 加密 → 儲存 → 讀取 完整時序

| 步驟 | 技術組件 | 發生什麼事 |
|---|---|---|
| 1. 登入 | Web3Auth | 家屬用 Google/LINE 登入，獲得 MPC 錢包 |
| 2. 加密 | Lit Protocol | 設定「持 NFT 才能解密」規則，把照片變亂碼 |
| 3. 儲存 | Arweave / Irys | 把加密亂碼 + 存取規則永久存入 Arweave |
| 4. 驗證 | ERC-721 NFT | 區塊鏈記錄誰是合法繼承人 |
| 5. 讀取 | Lit + NFT | 確認家屬有 NFT → Lit 授權解密 → 家屬看到照片 |

## 五、儲存層：Arweave + Irys

### 5.1 放什麼、怎麼放（分層儲存）

| 資料類型 | 位置 | 是否加密 | 讀取時機 |
|---|---|---|---|
| 公開 metadata（姓名/生卒/大頭照/生平） | Arweave，寫入 NFT `tokenURI` | 否（公開） | 前端秒讀 |
| 私密原始檔（相簿/影片/錄音/日記） | Arweave permaweb | 是（Lit 加密） | 深度追思才抓 |
| 對話紀錄（LINE/WhatsApp/FB…） | Arweave | 是（含活人，務必加密） | AI 訓練時 |
| AI 訓練產物（LoRA/聲音/RAG 索引） | Arweave，指針寫入 `artifactURI` | 是 | 啟動分身時 |
| 公祭留言 | **平台 Postgres（短期，非 Arweave）** | 否 | 公祭期間 |

> **公祭留言為何不上 Arweave**：留言是臨時互動，永久上鏈成本高且無必要。存 DB、保留 90 天後清除；家屬可把「精選留言」另存永久。

### 5.2 Irys 的角色

Irys（原 Bundlr）是 Arweave 的上傳加速層：

- 把多個檔案打包（bundle）成一筆交易上傳，省錢省時
- 支援 >200MB 大檔高速上傳
- 前端可用 `@irys/sdk` 直傳，不經後端中轉，省頻寬

### 5.3 上傳流程

```
前端選檔
  → Lit Protocol 加密（私密檔案）
  → Irys 切片打包上傳至 Arweave
  → 取得永久 TXID
  → 組 metadata JSON（含 TXID 指針）
  → 上傳 metadata 取得 metadata TXID
  → 呼叫合約 safeMintWithParent(parentId, "ar://<metadata-txid>")
```

### 5.4 Arweave 經濟學與 AR 幣（演算法說明）

**一次付費、永久保存怎麼做到？**

1. **儲存捐贈基金（Storage Endowment）**：上傳時一次付清 AR，大部分進入基金池，不立即發給礦工。
2. **基金吃利息、緩慢釋放**：演算法假設「儲存硬體成本逐年下降」（歷史上每 GB 成本指數下滑），一筆本金的利息足以支付越來越便宜的長期儲存。
3. **隨機存取證明（SPoRA）**：礦工挖礦時被隨機抽考歷史資料片段，必須立刻提出才能挖到區塊 → 礦工存越多歷史資料，挖礦成功率越高 → **保存資料 = 賺錢**。
4. **去中心化備份**：全球數百節點各持副本，無單點故障。

**AR 幣兩個用途**：付儲存費、獎勵礦工。家屬不直接接觸 AR——平台在背後用法幣換 AR 代付（見商業模式文件第七節）。

## 六、運算層：AI 怎麼跑

這是「AI 部分怎麼跑」的完整說明。AI 分**離線訓練**與**線上推理**兩階段。

### 6.1 離線訓練（建模，一次性，跑在 GPU 機）

家屬上傳素材後，觸發一條訓練 pipeline（開發/營運方的 GPU 機執行）：

```
01 從 Arweave 拉素材（Lit 解密）
02 BLIP-2 / LLaVA 自動為照片打標
03 SDXL + LoRA 微調（rank 16/32，person 類別）   → 學會逝者長相
04 ElevenLabs 聲音克隆（從生前錄音建立 voice）    → 學會逝者音色語調
05 日記/對話切片 + embedding → 向量庫              → 建立記憶 RAG 索引
06 打包成 artifact（LoRA + voiceId + RAG + manifest）
07 加密後上傳 Arweave → 回填合約 artifactURI
```

> **聲音為何用 ElevenLabs**:逝者建議用其「專業語音克隆(PVC)」,需至少 30 分鐘生前錄音(3 小時最佳),產出幾乎與本人無法區分的聲音;素材少時可用「即時克隆(IVC)」,1–5 分鐘錄音即可。克隆完成後得到一個 `voiceId`,存入 artifact manifest,推理時用此 ID 即時生成語音(無需自存大型聲音模型權重)。

**GPU 來源**：自架（RTX 4090 / A6000 等級）或雲端 GPU（DataCrunch、RunPod、Akash 等）。Prototype 階段建議自架單機，省雲端成本。

### 6.2 線上推理（互動時即時跑）

家屬點「啟動數位分身」後：

```
1. 錢包簽名（SIWE）→ 後端查 ownerOf 驗證持有
2. Lit 授權 → 從 Arweave 下載並解密 artifact
3. 載入模型（lazy load + LRU 快取在 /tmp/persona_cache/<tokenId>）
4. 三軌 + 視訊同步：
   ├─ 對話：RAG 檢索記憶 + LLM 生成（以逝者口吻）
   ├─ 聲音：ElevenLabs 把文字轉成逝者的克隆聲音（WebSocket 串流）
   ├─ 外貌：LoRA 生成逝者影像（靜態畫面 / 餵給 Simli 的臉孔）
   └─ 視訊：Simli 把「聲音 + 臉」即時合成為會說話的視訊化身
5. 互動結束 → 快取 5 分鐘後 GC 刪除，原始資料永留 Arweave
```

### 6.3 聲音層：ElevenLabs（語音克隆 + 即時串流）

**ElevenLabs 是什麼**:業界最自然的 AI 語音平台,負責「把逝者的聲音複製出來,並把任何文字用那個聲音念出來」。Simli 只做臉(對嘴+表情),**聲音必須由 ElevenLabs 提供**,兩者分工。

重點特性:
- **語音克隆兩模式**:專業克隆(PVC)需 30 分鐘以上錄音、效果近乎本人;即時克隆(IVC)1–5 分鐘即可、幾秒生成
- **低延遲串流**:串流 TTS 在多數地區延遲低於 300ms,Flash 模型專為即時對話設計、每字元只算 0.5 credit
- **WebSocket 串流 API**:可即時把音訊串流餵給 Simli,支援 29+ 語言(中英混合友善)
- **成本**:用量計費,即時對話用 Flash 模型省一半 credit;注意「低延遲 TTS」在部分自助方案有層級限制,上架前需依官方 docs 確認方案

### 6.4 Simli 整合（即時視訊化身）

**Simli 是什麼**：一個讓 AI 化身「會即時說話、有生動表情」的後端技術服務。重點特性：

- **Gaussian Splatting 技術**：高畫質、表情生動、可從單張照片複製臉孔
- **<300ms 超低延遲**：專為對話設計，視訊體驗如打視訊電話般順暢
- **WebRTC 傳輸**：原生支援 **LiveKit** / Pipecat 框架，Web/手機/桌面皆可——與公祭房間共用同一套基礎設施
- **成本**：Trinity-1 模型可低至每分鐘約 US$0.01（市場行情多為 5–20 美分）；新用戶有 US$10 免費額度、每月 50 分鐘

**完整即時互動鏈路（聲音 + 影像 + 傳輸）**：

```
逝者臉孔來源（LoRA 生成的高清臉 或 生前真實照片）
  → 在 Simli 建立 custom avatar（臉孔模型）

互動時：
  RAG + LLM 產生回覆文字
    → ElevenLabs 用逝者 voiceId 即時生成語音（Flash 模型, WebSocket, PCM 16kHz）
    → 音訊串流推送給 Simli API
    → Simli 即時合成「對嘴 + 表情」視訊（<300ms）
    → LiveKit（WebRTC）把視訊串流到家屬瀏覽器
```

**總延遲預算**:LLM 首 token + ElevenLabs(<300ms) + Simli(<300ms),整體可控制在「視訊通話級」的順暢度。

**為什麼用 Simli + ElevenLabs 而不自建**：自建 LivePortrait + GPT-SoVITS 等級的即時視訊化身需要大量 GPU 與工程;用兩個成熟 API 幾分鐘接上、各自 <300ms 延遲、按分鐘計費,對上架產品是最務實選擇。LoRA 仍保留用於生成靜態影像與餵給 Simli 的臉孔來源。

### 6.5 線上公祭房間（你要的「GeoGuessr 開房」功能）

採用 **LiveKit** 作為公祭的 WebRTC 基礎設施——因為 Simli 原生支援 LiveKit,公祭房間與 AI 視訊化身**共用同一套 WebRTC**,不必接兩套。

```
持有人開房 → 後端產生房號 + LiveKit Room
親友憑連結進房（免帳號也可觀看）
房內：
  ├─ AI 爺爺作為一個「虛擬參與者」進房主講
  │     （ElevenLabs 聲音 + Simli 影像,以 participant 身分加入）
  ├─ 親友的多人視訊 / 語音連線（LiveKit SFU,擅長多人）
  └─ 即時留言 / 彈幕（LiveKit Data Channel,不佔音視訊頻寬）
公祭結束 → 留言存短期 DB,90 天後清除,精選留言可另存永久
```

**部署選擇**:LiveKit 有開源自架版(省錢、資料自控)與 LiveKit Cloud(省維運);prototype 建議先用 Cloud,規模大再評估自架。需留意公祭「瞬間多人進房」的流量尖峰與 AI 化身按分鐘計費的成本。

## 八、資料流：從鑄造到互動的完整生命週期

```
【建立階段】
家屬登入(Web3Auth) → 填資料 + 上傳素材
   → Lit 加密 → Irys 上傳 Arweave → 取得 TXID
   → 組 metadata → 鑄造 ERC-721/6150 NFT（鏈上）
   → GPU 跑訓練 pipeline → artifact 加密上傳 → 回填 artifactURI

【互動階段】
家屬點「啟動分身」
   → SIWE 簽名 → 後端查 ownerOf 驗證
   → Lit 核對 NFT 持有 → 授權解密
   → 下載解密 artifact → 載入 LoRA / RAG / 取得 ElevenLabs voiceId
   → RAG+LLM 生成回覆 → ElevenLabs 轉聲音 → Simli 合成視訊 → LiveKit 串流
   → WebRTC 串流到家屬畫面
   → 結束後快取清除，原始資料永留 Arweave

【傳承階段】
持有人定期 heartbeat 維持活躍
   → 若逾期未活躍 → 死亡開關觸發
   → 繼承人 claimInheritance → 接手家族塔位
```

## 九、安全、隱私與倫理

| 風險 | 緩解 |
|---|---|
| NFT 公開可查，但私密檔案外洩 | Lit Protocol 加密，僅持 NFT 者能解密；鑰匙碎片化 |
| 對話紀錄含活人隱私 | 強制加密 + 「僅上傳逝者單方訊息」過濾選項 + UI 明確警示 |
| NFT 失竊導致記憶被劫持 | 社群復原 / 多簽 hook |
| 持有人過世記憶斷層 | 死亡開關自動移交繼承人 |
| 未經逝者同意建模 | 鑄造強制勾選同意聲明，並上鏈存證 |
| 平台倒閉 artifact 無人能解讀 | manifest 採開放格式（safetensors + 標準 RAG schema）+ 公開文件 |
| 塔位被投機炒作 | 合約限制僅能在已驗證家族成員間轉移 |

## 十、為什麼這個架構「可上架、可公布」

1. **無 Web3 門檻**：Web3Auth 讓家屬用 Google 登入即可，不嚇跑一般使用者。
2. **真實去中心化**：所有權在鏈、資料在 Arweave、鑰匙在 Lit——平台倒了資料還在，可驗證的「數據主權」而非行銷話術。
3. **AI 體驗到位**：RAG+LLM(記憶對話) + ElevenLabs(聲音) + LoRA+Simli(視訊化身) + LiveKit(串流)，逝者「活過來」而非靜態相簿。
4. **成本可控**：儲存一次付清、AI 互動按量計費、Simli 每分鐘成本低，財務模型可持續。
5. **金流合規**：法幣入金外包給持牌 On-ramp，KYC/AML 不自己扛。
6. **倫理有防線**：同意上鏈、家族驗證、禁止投機、死亡開關——降低法律與聲譽風險。

> 透過區塊鏈不可篡改性確立家族位階，透過 Arweave 永久儲存封裝遺產，透過 Lit Protocol 守護隱私，透過生成式 AI 與 Simli 賦予數據生命。這是在數位荒野中，為每個人建立一座永不熄滅的燈塔。
