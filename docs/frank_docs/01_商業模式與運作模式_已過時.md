# DSAS 商業模式與運作模式

> **DSAS — Data Sovereignty as Soul（數位塔位 / 主權數位先祖系統）**
> 一個結合區塊鏈、去中心化儲存與生成式 AI 的數位永生服務。家屬透過 NFT 擁有逝者的數位分身，並能與其互動（對話、影像、聲音）。
>
> 本文件回答：**使用者如何使用平台、各項資產歸屬於誰、人死後怎麼處理、要花多少錢、怎麼維護、平台怎麼賺錢、加密貨幣與法幣如何兌換。**

---

## 一、核心定位：我們在賣什麼

我們不是賣「一個 App 帳號」，而是賣**一份永遠屬於你家族、且永不依賴本平台存活的數位遺產**。

| 痛點 | Web2 現況 | DSAS 解法 |
|---|---|---|
| 記憶是租來的 | 照片放 Google Drive / iCloud，平台倒了、欠費了就消失 | 一次付費永久存於 Arweave，平台倒了資料還在 |
| 帳號會消失 | 20 年後帳密失效、多個帳號散落各處 | NFT 錢包 = 唯一鑰匙，所有權寫在鏈上 |
| 記憶是死的 | 只剩靜態相片與影片 | 生成式 AI 讓逝者「會說話、有表情、能對話」 |
| 隱私無法掌控 | 平台看得到你所有檔案 | Lit Protocol 加密，只有持 NFT 者能解密 |

**一句話商業定位**：我們是「數位時代的宗祠 + 永久保險箱 + 會說話的祖先」，賣的是**主權**與**永恆**。

## 二、使用者旅程：一個家庭怎麼用這個平台

下面用「王家爸爸幫過世的爺爺建立數位塔位」的故事走一遍完整流程。

### 階段 0：註冊（降低 Web3 門檻）

**問題**：一般家屬不懂什麼是錢包、私鑰、助記詞。

**解法**：採用 **Web3Auth（MPC 錢包）** ，讓家屬用 **Google / LINE / Email 一鍵登入**，背後自動生成一個錢包。

- 使用者體感：跟登入任何 App 一樣，輸入 Google 帳號即可
- 實際發生：系統用 MPC（多方計算）技術生成一個錢包，私鑰碎片分散保管，使用者不需要抄助記詞
- 進階使用者：仍可選擇連接自己的 MetaMask / Rabby，把資產轉到自持錢包

> **這就是你說的「用 Google 帳號方式先擁有」**——完全可行，而且是目前 Web3 降低門檻的主流做法。家屬之後若想完全自主，隨時能把 NFT 轉到自己的硬體錢包。

### 階段 1：鑄造爺爺的數位塔位（Mint）

王爸爸登入後，點「建立塔位」，分三步：

1. **填基本資料**：姓名、性別、籍貫、生卒年月日、生平、墓誌銘
2. **上傳素材**：照片、影片、錄音、日記文章、與爺爺的對話紀錄（LINE / WhatsApp / FB 匯出檔）
3. **簽署同意聲明 + 鑄造**：勾選「本人聲明持有逝者肖像／聲音／文字之使用同意」，錢包簽名，鑄出一張 **ERC-721 NFT**

完成後，鏈上就有一張「爺爺的數位塔位」，王爸爸是持有人。

### 階段 2：家族樹——純逝者譜（方案 A）

> **重要設計原則:塔位 NFT 只為「已逝者」鑄造,活人不鑄 NFT、不進家族樹節點。**

這是本系統的核心取捨。塔位是「緬懷逝者」的載體,因此:

- **只有逝者擁有 NFT 節點**。家族樹是一棵「純逝者譜」——爺爺、奶奶、太爺爺等已逝者才是樹上的節點。
- **活人不是節點,而是「持有者 / 守護者」**。活著的王爸爸不鑄自己的 NFT,他的角色是**持有並管理**爺爺的塔位(錢包持有 NFT = 守護者)。
- **家譜如何延伸**:當王爸爸日後過世,家屬才為他鑄造塔位 NFT,並用 `safeMintWithParent(爺爺tokenId)` 把爸爸接到爺爺底下,家族樹自然往下長一代。

```
純逝者譜（只有已逝者是節點）

太爺爺 (根 NFT)
   └── 爺爺 (子 NFT, safeMintWithParent 接在太爺爺下)
         └── (爸爸還活著 → 沒有節點,他是爺爺塔位的「守護者」)

         ↓ 多年後爸爸過世 ↓

太爺爺 (根 NFT)
   └── 爺爺 (子 NFT)
         └── 爸爸 (新鑄子 NFT, 接在爺爺下) ← 家譜往下長一代
               └── (你還活著 → 你是守護者,尚無節點)
```

**這樣設計的好處**:
- 概念純粹:NFT = 逝者塔位,不會出現「幫活人鑄 NFT」的倫理與隱私尷尬
- 鏈上即家譜:ERC-6150 的父子關係只記錄逝者血緣,不需外部資料庫
- 守護者清楚:任一時刻,每張塔位都有明確的「當前持有錢包」負責管理

**「邀請家族成員」怎麼運作(不發 NFT)**:王爸爸想讓叔叔、姑姑一起管理或瀏覽爺爺的塔位時,**不是發子 NFT 給他們**,而是把他們的錢包地址登記為該塔位的「共同守護者 / 可瀏覽者」(鏈上授權地址 + 角色)。這比較像 GitHub 的 collaborator——repo(塔位)只有一個,但可以授權多人不同權限(瀏覽 / 上傳 / 管理),而不是每個 collaborator 都複製一份 repo。

> **與 GitHub 的精確對應**:塔位 NFT = repo;持有人 = repo owner;被授權的家族成員 = collaborator(有 read / write / admin 之分);ERC-6150 父子關係 = 逝者之間的血緣鏈,與「誰能存取」是兩回事。

### 階段 3：設定公開 / 私密（權限控管）

塔位持有人(守護者)可逐項決定每個檔案的可見範圍：

| 範圍 | 誰能看 | 典型內容 |
|---|---|---|
| **公開（Public）** | 任何人（含區塊鏈上的路人） | 姓名、生卒年、大頭照、生平、家族徽章 |
| **家族（Family）** | 被授權的家族成員錢包 | 私人相簿、家庭影片、錄音 |
| **私密（Private）** | 僅持有人 / 特定錢包 | 含活人的對話紀錄、敏感遺物 |

切換方式：王爸爸在前端點「切換公開」→ 錢包跳出簽章 → 簽章修改鏈上合約狀態 → 同步通知 Lit Protocol：「規則改了，路人來要鑰匙也可以給」。

### 階段 4：與爺爺的數位分身互動

家屬點「啟動數位分身」：

1. 錢包簽名（SIWE，純訊息免 gas）證明「我持有這張 NFT」
2. Lit Protocol 核對通過 → 集體解密 → 取出加密的相簿 / AI 模型
3. AI 五件套協作即時重現逝者：
   - **RAG**:檢索逝者生前日記、對話的記憶片段
   - **LLM**:以逝者口吻生成回覆文字
   - **ElevenLabs**:把文字轉成逝者的克隆聲音(從生前錄音複製音色)
   - **Simli**:把聲音 + 臉即時合成「會說話、有表情」的視訊化身
   - **LiveKit**:用 WebRTC 把視訊低延遲串到家屬畫面
4. 家屬可以打字或說話，爺爺用熟悉的臉、聲音、口吻**即時視訊對話**

> 技術細節(各組件如何串接、延遲、成本)見系統架構文件第六節。

### 階段 5：線上公祭（房間制）

> **你想要的「像 GeoGuessr 那樣開房間」的線上公祭功能。**

- 持有人開一個「公祭房間」，產生一條分享連結 / 房號（底層用 **LiveKit** 建立 WebRTC 房間）
- 親友（即使沒帳號）可進房，一起觀看爺爺的紀念影像、聽 AI 爺爺說話
- AI 爺爺以一個「虛擬參與者」身分進房主講(ElevenLabs 聲音 + Simli 影像)
- 房內可即時留言（彈幕 / 留言板，走 LiveKit Data Channel，不佔音視訊頻寬）
- **留言儲存策略**：公祭留言屬於「臨時性互動」，**不需要永久上鏈**。存於一般資料庫（Postgres），保留例如 90 天後自動清除，或由家屬選擇「精選留言」才寫入永久儲存。這樣省成本又合理——詳見架構文件。

## 三、資產歸屬：每樣東西是誰的

這是整個商業模式最核心、也最需要講清楚的部分。

| 資產 | 技術載體 | 法律 / 實質歸屬 | 平台能不能碰 |
|---|---|---|---|
| **數位塔位本體（身分）** | ERC-721 / ERC-6150 NFT | **持有該 NFT 的錢包（家屬）** | ❌ 平台無法奪取、無法刪除 |
| **原始檔案（照片/影片/音檔/文字）** | Arweave（加密） | **家屬**（內容定址，永久存在） | ❌ 平台只是上傳代理，無法刪改 |
| **解密權限** | Lit Protocol | **持 NFT 者**（合約邏輯決定） | ❌ 平台無單獨解密能力 |
| **AI 訓練產物（LoRA/聲音/RAG）** | Arweave（加密） | **家屬** | ❌ 同上 |
| **離鏈快取與索引** | 平台 Postgres / Redis | 平台（僅為加速，非權威來源） | ✅ 可重建，刪了不影響資產 |
| **公祭留言** | 平台 DB（短期） | 留言者 / 家屬 | ✅ 屬臨時資料 |

**核心承諾**：平台是「服務商」不是「保管人」。即使本平台明天倒閉，只要 Arweave 還在、家屬持有 NFT 錢包，任何懂技術的人都能用 NFT 指向的 TXID 把資料抓回來、用開放格式的 manifest 重現逝者。**這是賣點，也是法律上的免責結構。**

## 四、人死後怎麼辦：繼承與「死亡開關」

數位永生服務最尖銳的問題：**持有人自己死了，記憶會不會一起陪葬？**

### 機制一：預設繼承人（Successor）

鑄造時，持有人可在合約中指定「繼承人錢包」。類似遺囑的鏈上版本。

### 機制二：死亡開關（Dead Man's Switch）

合約設定一個「活躍度計時器」：

- 若主 NFT 持有人連續一段時間（例如 12 個月）未登入 / 未做任何鏈上互動
- 合約自動把控制權（根 NFT）轉移給預設的繼承人錢包
- 繼承人收到通知，接手家族塔位的管理權

> 這樣即使第一代家屬全數離世，只要有設定繼承鏈，數位塔位就能一代代傳下去——真正的「數位宗祠永續」。

### 機制三：社群復原（Social Recovery，進階）

為防 NFT 失竊或私鑰遺失導致「記憶被劫持」，可設定多簽（multisig）或社群復原：需家族多位成員共同簽署，才能轉移最高權限。

## 五、花費：使用者要付多少錢

DSAS 的成本結構分「一次性」與「持續性」兩塊。

### 5.1 一次性費用（建立塔位時）

| 項目 | 性質 | 說明 |
|---|---|---|
| **永久儲存費** | 一次付清，永久有效 | 依檔案大小計算的 Arweave 儲存成本 + 平台服務費 |
| **鑄造 gas 費** | 一次性 | 鏈上鑄造 NFT 的手續費（用低 gas 鏈如 Polygon / Base，成本極低） |
| **AI 建模費** | 一次性（可選） | 訓練 LoRA + 聲音 + RAG 的 GPU 算力成本 |

### 5.2 持續性費用（使用時）

| 項目 | 性質 | 說明 |
|---|---|---|
| **AI 互動費** | 用多少付多少 | 對話 / 視訊化身的推理算力:Simli 視訊約每分鐘 US$0.01–0.05、ElevenLabs 聲音約每分鐘數美分、LLM token 費 |
| **訂閱（可選）** | 月費 / 年費 | 包含一定額度互動、進階功能、家族空間擴充 |

### 5.3 為什麼儲存是「一次付費、永久保存」——Arweave 的經濟學

這是常被問的關鍵問題：**「你怎麼保證我付一次錢，200 年後資料還在？」**

Arweave 的設計是這樣運作的（白話版）：

1. **你付的錢不是「月租」，而是一筆「儲存捐贈基金（Storage Endowment）」**
   - 上傳檔案時，你一次付清一筆 AR 代幣
   - 這筆錢大部分不會馬上給礦工，而是放進一個「基金池」

2. **基金池吃利息，慢慢釋放給礦工**
   - 演算法的假設：**儲存硬體的成本每年都在下降**（過去 50 年硬碟每 GB 成本指數級下滑）
   - 所以一筆錢產生的利息，足以支付「越來越便宜」的儲存成本
   - 礦工為了領這筆持續釋放的獎勵，會競爭性地證明「我還保存著這份資料」

3. **礦工怎麼證明他真的存著？——SPoRA / 隨機存取證明**
   - Arweave 要求礦工「隨機抽考」：系統隨機挑一個歷史區塊的資料片段，礦工必須能立刻提出來才能挖到新區塊
   - 礦工存的歷史資料越完整，挖礦成功率越高
   - 結果：**礦工的最佳策略就是盡可能保存所有資料**——保存資料 = 賺錢

4. **多重備份，去中心化**
   - 全球數百個獨立節點各自保有副本
   - 沒有單點故障，沒有「公司倒了伺服器關機」的問題

> **這就是為什麼 Arweave 被稱為「數據的比特幣」**：用經濟誘因，讓「永久保存」變成礦工自願且有利可圖的行為，而不是靠一家公司的良心。

### 5.4 AR 幣怎麼運作

- **AR 是 Arweave 網路的原生代幣**，用途有二：付儲存費、獎勵礦工
- 使用者**不需要直接接觸 AR**：平台在背後幫你把法幣 / USDC 換成 AR 去付儲存費（見第七節）
- 家屬體感：你只看到「儲存費 NT$XXX」，平台處理掉所有加密貨幣的複雜性

## 六、平台怎麼賺錢

清楚的營收結構是「可上架、可公布」的前提。DSAS 有五條營收線：

### 6.1 儲存服務費（一次性，主力）
家屬付的「永久儲存費」中，包含 Arweave 實際成本之上的**服務加成（markup）**。例如實際儲存成本 NT$300，平台收 NT$800，差額為毛利。一次性、隨建立塔位數量規模化。

### 6.2 AI 建模費（一次性）
訓練 LoRA + 聲音模型 + RAG 索引的 GPU 算力，平台收取建模服務費。

### 6.3 AI 互動費 / 訂閱（持續性，長尾）
- 用量計費：視訊化身、語音對話按分鐘計費（成本 Simli + ElevenLabs + LLM token 費，向上加成）
- 訂閱方案：家族年費，含互動額度與進階功能（家族樹擴充、公祭房間、優先算力）

### 6.4 公祭 / 紀念活動加值服務
- 線上公祭房間（大型場次、客製主題、紀念影片製作）
- 重要忌日的 AI 主動關懷推播（加值訂閱）

### 6.5 交易手續費（二級市場，長期）
數位塔位作為 NFT 可在家族間轉移、繼承。若未來開放家族紀念性收藏品（如「回憶資產化」子 NFT）的流轉，平台可收取轉移手續費。

> **倫理紅線**：逝者塔位本身不應被當投機商品炒作。建議契約上限制塔位 NFT 僅能在「已驗證家族成員」間轉移，避免變成投機標的，這也是品牌信任的關鍵。

## 七、加密貨幣與真實資產兌換：第三方交易所的角色

家屬不該需要懂加密貨幣。平台用以下方式把複雜性藏起來：

### 7.1 法幣入金（Fiat On-ramp）

整合第三方法幣通道，讓家屬用**信用卡 / Apple Pay / 銀行轉帳**直接付款：

- **第三方 On-ramp 服務**：如 MoonPay、Transak、Ramp Network 等
- 流程：家屬刷卡付 NT$ → On-ramp 服務商把法幣換成 USDC / AR → 自動進入支付流程
- 家屬全程只看到「NT$ 金額」，不碰任何加密貨幣

### 7.2 平台代付儲存（最簡模式，推薦 prototype 用）

更簡單的做法：**家屬付法幣給平台，平台用自己的金庫去買 AR 付 Arweave**。

- 家屬：刷卡付台幣
- 平台：批次把營收換成 AR / USDC，統一支付儲存成本
- 好處：家屬零學習成本；平台可批次換匯、議價、對沖匯率風險

### 7.3 為什麼需要第三方交易所協助

- **匯率與流動性**：AR / USDC 對法幣的兌換需要有深度的交易所（如 Binance、Coinbase、Kraken）提供流動性
- **合規 KYC/AML**：法幣進出需要持牌機構處理身分驗證與反洗錢，平台自己做成本極高，外包給 On-ramp 服務商最務實
- **匯率波動對沖**：AR 幣價會波動，平台需透過交易所做避險，確保「一次付費永久儲存」的承諾在財務上可持續

### 7.4 結論

| 角色 | 做什麼 |
|---|---|
| **家屬** | 只付法幣，全程不碰加密貨幣 |
| **平台** | 收法幣、管理金庫、批次換匯、支付鏈上成本 |
| **第三方 On-ramp（MoonPay/Transak）** | 法幣 ↔ 加密貨幣即時兌換、KYC |
| **第三方交易所（Binance/Coinbase）** | 提供 AR/USDC 流動性、平台金庫換匯與避險 |

## 八、維護：平台長期怎麼運作

| 維護面向 | 做法 |
|---|---|
| **資料永續** | Arweave 本身保證（去中心化、經濟誘因），平台不需自建儲存機房 |
| **離鏈服務** | 前端（Vercel）、後端 API、AI 推理服務需持續運維，由訂閱與互動費支撐 |
| **AI 模型更新** | 基礎模型（SDXL / LLM / Simli / ElevenLabs）持續升級，舊 artifact 用開放格式（safetensors）確保向後相容 |
| **格式可讀性** | manifest 採開放標準並公開文件，確保「即使平台消失，artifact 仍能被任何人解讀」 |
| **安全** | 私鑰相關走 MPC / 多簽；定期安全稽核；死亡開關與社群復原機制 |
| **倫理治理** | 同意聲明上鏈、家族驗證機制、塔位禁止投機炒作 |
